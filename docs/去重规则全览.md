## 一、总览：三条判重链路 + 一层母子卡

去重不是「一个函数」，而是**按抓取时机分成的三条独立链路**，这是理解全部问题的前提。

| 链路 | 入口 | 何时跑 | 窗口 | 调用的判据 |
|---|---|---|---|---|
| **同轮去重** | `dedupe(items)` `4828` | `LiveNews.collect()` 单轮抓完一批后 | **3 天** | `sameNews` → `sameSyncEvent` → `sameGeoEvent` → `sameCorpPersonnel` → **`sameNewsBody`** → `sameMoveBurst` |
| **跨轮去重** | `findDup(list, it, win)` `4775` | APP 运行时轮询 `pollFlash`（`app.js:5904/6002`）、回溯 collect（`6618`） | **6 小时**（调用方传入） | `containsOther`（长度豁免）→ `sameNorm` → `sameSyncEvent` → `sameMoveBurst` → `sameNews` → `sameGeoEvent` → `sameCorpPersonnel` |
| **存量窄合并** | `mergeGeoDup(items)` `4894` | APP 启动时清空存量重复（`app.js:5842`） | **6 小时** | **只跑** `sameGeoEvent` + `sameCorpPersonnel` |
| **母子卡分组** | `clusterKey(title)` `4635` | 渲染时（`app.js:1009/1069/1227`） | 无 | `syncOrgOf + syncTopicOf`，**不删条目**，只把同机构同议题聚成一张母卡带 N 条进展 |

**另有按 id 的硬去重**：`app.js:5822` 的 `liveIds` Set —— 同一帖子重复抓取直接挡掉，不进标题判重。

> ⚠️ 源码 `3744–3760` 的注释写着「现在统一成一套内核，同轮 `dedupe()` 与跨轮 `findDup()` 共用」、
> `6618` 写着「用与 pollFlash 完全一致的内核判重」。**实测并不完全一致**，见 §7.1。

**订阅源豁免**：`NO_MERGE_SRC = /川普言论|口罩哥KZG/`（`4756`）—— 用户口径「图二是川普的推文，所以可以不用合并，虽然是一个事情」。
原始推文与媒体转述稿都该各自可见，同一帖子的重复只靠 `liveIds` 挡。三条链路与 `mergeNews` 都做了这个豁免。

## 二、执行链路：一条快讯经过的所有手

```
抓取（多源）
  ↓  liveIds 按 id 硬去重（app.js:5822）
  ↓  enrich() 分级 / 打标（3609）  ← C 级直接不入池
  ↓
  ┌──────────── 同轮 collect ────────────┐
  │ dedupe() 4828：倒序 → 逐条与 kept 比   │
  │   3 天窗 → 6 条判据 → 正文交叉 → 同波  │
  └──────────────────────────────────────┘
  ↓  合并命中 → mergeNews() 4664（改标题/重算级别/互补标的）
  ↓
  池子 S.news
  ↓  运行时 pollFlash 每轮新增 → findDup() 4775（6h 窗，跨轮）
  ↓  启动时 mergeGeoDup() 4894（只清地缘 + 人事两类存量重复）
  ↓
  渲染 → clusterKey() 4635 母子卡分组（不删）
```

**关键顺序**：判重发生在 **enrich 之后、渲染之前**。所以 `mergeNews` 里会按**合并后的最终标题重算分级** —— 这是分级与去重两条链路唯一的交汇点，也是历史上「用户改判被覆盖」的高发区（`4702–4710` 有 `!target.fixed` 保护）。

## 三、判据执行顺序（按源码真实顺序）

### 3.1 归一化层

| 函数 | 行 | 作用 |
|---|---|---|
| `ratio(a,b)` | 1798 | 二元组 Dice 系数：`2*hit / ((len_a-1)+(len_b-1))`，近似 `SequenceMatcher.ratio` |
| `normTitle(s)` | 3764 | 剥 `TITLE_NOISE` 栏目前缀 → 去空白 → 只留中英文数字 |
| `numsOf(s)` | 3771 | 抽所有 ≥2 位数字 |
| `numConflict(a,b)` | 3783 | **两边都有数字且零重合 → 两件不同的事**（守门核心） |
| `similarity(a,b)` | 3792 | 相等=1；一方包含另一方 → `0.5+0.5*短/长`；否则 `ratio` |
| `canonClaim(s)` | 3967 | 数字抽走 → `DEDUP_SYN` 近义改写 → 去停用词 → 去标点 |
| `looseNorm(s)` | 4759 | 轻归一，只去空白标点，**不剥前缀**（给 `containsOther` 用） |
| `sharedRun(a,b)` | 4249 | 最长公共连续子串（O(n·m) DP，标题短，开销可忽略） |

`DEDUP_SYN`（`3934`，**顺序敏感**）是跨源改写的核心：
`没有/暂无/无意→非`、`打击/袭击/空袭→打`、`立即→即`、`表示/称/指出→述`、
`引发/导致→致`、`起火/火灾→火`、`俄罗斯/俄方/俄军→俄`、`当局/官方→''`、
职衔词（总统/主席/行长/委员…）整体删除。共 **18 组**。

### 3.2 槽位层（防「同骨架不同数字」误合）

`DEDUP_NUM_RULES`（`3976`）把数字按**角色**分槽，共 9 条：
`date` / `year` / `bp`（基点，2 条）/ `ppt`（百分点）/ `amt`（金额）/ `px`（价位）/ `pct` / `level`（关口）。

`DEDUP_GEO`（`3988`，48 个国家）/ `DEDUP_ORG`（`3994`，19 个机构）另作实体槽。

`slotConflict()`（`4032`）遍历 10 个 kind，判据是 **`subsetOf` 双向都不成立才冲突**：
一边多提一个国家只算详略不同（子集放行），两边互不包含才判冲突。
> 这条是 v? 修过的：原实现要求集合完全相等，导致「A 标题多写一个错译国家」就被拆成两条。

### 3.3 `sameNorm()` `4056` — 纯字面判定（7 步）

| # | 条件 | 返回 |
|---|---|---|
| 1 | `min(len) < 8` | `false` |
| 2 | `a === b` | `true` |
| 3 | `thresholdKey(a) && thresholdKey(b)`（品种+价位+方向三元组，`3887`） | 相等即 `true` |
| 4 | `releaseKey(a) && releaseKey(b)`（主体+指标+期别，`3843`） | **相等即 `true`，不等直接 `false` 短路** |
| 5 | `numConflict(a,b)` | `false` |
| 6 | 前 12 字相同 | `true` |
| 7 | 两边 ≥10 且一方整句包含另一方 | `true` |
| 8 | `similarity(a,b) >= 0.82` | `true` |

> 第 4 步的短路是有意的（注释：`主体/指标/期别 不同 → 一定是两件事，别再按字面相似度硬凑`），
> 但也意味着 **`releaseKey` 一旦误识别就没有补救**，见 §7.2。

### 3.4 `sameClaim()` `4104` — 跨源同事件三道闸

```
① slotConflict(t1,t2) → false      数字/实体槽互不包含
② splitClaim() 4047 切掉主体前缀   「特朗普：XXX」→ 只比 XXX
③ 陈述都 ≥10 字：
     canonClaim 相等 / 短陈述是长陈述子串(≥10) / coveredBy 摘要式包含 / ratio ≥ 0.72
   否则退回整标题：canonClaim 长度 ≥6 且 ratio ≥ 0.86
```

`coveredBy()`（`4095`）三条件：短句 ≥7 字、长句 ≤ 短句 **2.6 倍**、短句每个字都在长句里出现过。

**`DEDUP_THR = 0.72`（`4080`）** 由 `tools/proto_dedupe.py` 在 227 条真实语料上标定：
0.72~0.80 输出完全一致（7 组全对），**0.66 会多合一组错误**。

### 3.5 `sameNews()` `4268` — 主判定 9 个短路分支（★ 按源码顺序）

| # | 行 | 判据 | 命中 |
|---|---|---|---|
| 1 | 4272 | `FIRM_ACT` 两边都命中**且公司名不同** | `false`（丰田 vs 本田绝不合） |
| 2 | 4276 | `sameNorm(normTitle(t1), normTitle(t2))` | `true` |
| 3 | 4282 | 冒号后尾句 `tailOf` 两边 ≥8 字、无数字冲突、`similarity ≥ 0.8` | `true` |
| 4 | 4294 | 短标题 ≥12 字且 `sharedRun ≥ 12` 且 `≥ 短句*0.7` | `true` |
| 5 | 4312 | 无 `numConflict`、两边 ≥14 字、`sharedRun ≥ 13` | `true`（13 连字几乎不可能巧合） |
| 6 | 4316 | `sameFirmAction()` | `true` |
| 7 | 4327 | **贸易救济公告**：同发文机关 + 日期不冲突 + 商品不冲突（泛指「进口商品」按空处理） | `true` |

### 3.6 六大专项判据

| 判据 | 行 | 命中条件 |
|---|---|---|
| `sameSyncEvent` | 4504 | 同机构（`SYNC_ORG` 13 类）或同人物（`personHead`）/ 同议题（`SYNC_TOPIC` 7 类）/ 无数字冲突 / `dirConflict` 不打架 / 人物还要 `stanceConflict` 不打架 / 长度 ≥14（人物 ≥8）/ `similarity ≥ 0.35`（人物 ≥0.4）。方向词只在 `DIR_DECISIVE` 决定语境下才判冲突 |
| `sameGeoEvent` | 4581 | `GEO_ENTS` 13 类实体**有交集** + `GEO_ACTS` 5 簇动作**有交集** + 无数字冲突 + 城市不互斥（`GEO_CITIES`）+ **精细度闸**：公共串 ≥4 字 **或** 共享 ≥2 个动作簇。动作簇在 v57 拆细（原来 STRIKE 一簇把「爆炸」和「空袭致伤亡」误并） |
| `sameCorpPersonnel` | 4618 | 同公司实体（`corpOrgsOf`）+ 同人事动作类别（`leave`/`quit`/`appoint`）+ 无数字冲突。v59 补 |
| `sameMoveBurst` | 4196 | **2 小时**内 + 同向 + 幅度差 ≤**1.5 个百分点** + 非整数关口 + `tagAssets` 同标的。专治「跌5%→5.5%→6%」刷屏 |
| `sameNewsBody` | 4645 | **12 小时**内 + 正文首句 `leadOf` × 对方标题/正文 三组交叉比，无数字/槽位冲突、`canonClaim` 各 ≥8 字、`ratio ≥ 0.72`。专治「标题写错地点、正文才对」 |
| `sameProgression` | 4139 | 资金流类（净买入 60→70→100 亿）去数字后骨架**全等**；或两边都有百分比，只抹百分比、保留其它数字后骨架**全等**（不做模糊，防 81000/80000 关口误合） |
| `sameFirmAction` | 4235 | 同公司名（`firmNameOf`）+ 两边都有 `FIRM_ACT` 动作词 → 直接 `true`（**不校验是不是同一个动作**，见 §7.3） |

### 3.7 `dedupe()` `4828` — 同轮主循环

按 `ts` 倒序 → 每条 `it` 对已保留的 `kept` 逐条比：
1. `NO_MERGE_SRC` 直接入队（不参与任何合并）
2. 只比 **3 天**内（`3 * 86400000`）
3. 依次：`sameNews` → `sameSyncEvent` → `sameGeoEvent` → `sameCorpPersonnel`（后三条限 **6h** `SYNC_WIN`）
4. 都没命中 → `sameNewsBody`（12h）→ `sameMoveBurst`
5. 命中调 `mergeNews(dup, it)`；**合并后重算成 C → 从库里撤掉**
6. 返回 `kept`

### 3.8 `findDup()` `4775` — 跨轮

1. `NO_MERGE_SRC` 直接 `null`（新推文不合别人，也不被别人合）
2. 默认 **6h** 窗（调用方 `app.js` 与 `6618` 都显式传 `6*3600*1000`）
3. **长度预筛**：候选标题长度落在 `[0.4*len, 2.4*len]` 之外直接跳过 —— 0.82 相似度不可能出现在长度差 60% 以上的两条里
   - v126 豁免：超范围时用 `containsOther()` 兜一次「短标题被长标题整句包含」
4. 依次：`sameNorm` → `sameSyncEvent` → `sameMoveBurst` → `sameNews` → `sameGeoEvent`(6h) → `sameCorpPersonnel`(6h)
5. **没有 `sameNewsBody`** ← §7.1

### 3.9 `mergeNews()` `4664` — 怎么合（不是判不判）

| 项 | 策略 |
|---|---|
| 来源 | `src` 用 ` / ` 去重拼接 |
| 正文 | 取更长的 `brief`；`url` 补齐 |
| 不同口径 | `same=false` 时把对方标题写进 brief「另一口径：…」，**不吞数字** |
| 标题 | 中文优先（`cjkCount < 2` 让位）；同事件时取**信息更全的更长中文标题** |
| **级别** | **按最终标题重新 `grade()`**（不是取 max）—— 但 `!target.fixed` 才重算，保护用户手工改判 |
| 标红 | `important` 按 OR 合并、`impIdx` 取 max（v104：否则灰稿先入库会吞掉标红） |
| 标的 | **绝不跨类合并**：任一方是公司类就不并；宏观类互补后还要用 `finalText` 重新过滤美股（v93：换标题后别让旧个股继续挂母卡） |

## 七、已知结构性问题（重点 · 均带行号或实测输出）

### 7.1 【最严重】同轮 `dedupe` 与跨轮 `findDup` 判据不一致，注释承诺未兑现

- 注释 `3744–3760`：「现在统一成一套内核，同轮 `dedupe()` 与跨轮 `findDup()` 共用」；
  注释 `6618`：「用与 pollFlash 完全一致的内核判重」。
- 实际：`dedupe` 用 `sameNews`（内含 9 个分支）且**额外跑 `sameNewsBody` + `sameMoveBurst`**；
  `findDup` 用 `sameNorm`（只是 `sameNews` 的第 2 步）、**`sameNewsBody` 出现 0 次**，且多了长度预筛与 `containsOther`。
- 窗口也不一致：`dedupe` **3 天**，`findDup` **6 小时**。

**实测（干净对象，两条标题字面相似度 0.000，只有正文首句完全相同）**：
```
同标题判重 _sameNews : false
同轮 _dedupe([A,B])  : 1   （已合并）
跨轮 findDup([A],B)  : false（漏判 → 各占一张卡）
```
源码计数：`findDup` 体内 `sameNewsBody` = **0** 次，`dedupe` 体内 = **2** 次。

> **影响面**：真实运行时 `pollFlash` 每轮只抓几十条，绝大多数重复是**分两轮到达**走的 `findDup`。
> 也就是说「标题写错地点 / 只写结果、正文才对」这类重复，同轮能合、跨轮漏 —— 正是用户反复报
> 「同一个新闻出现好几次」的结构性根因。`v58 / v59` 的注释已分别记录过地缘、人事「只挂同轮、
> 运行时 findDup 没生效」并补了，但**正文判重这一路一直没补**。

### 7.2 【严重】`releaseKey` 注释承诺的「kind 兜底」没有实现

`3843–3861` 注释原文：
> 「初值 / 终值 不参与 key —— 它们本来就是同一份公报的不同阶段，
> 但「初值」和「终值」确实会给出不同数字，**用 kind 兜一层，隔太久不合并**。」

实际 `return geo + '|' + ind + '|' + per;` —— **没有 kind，也没有时间判断**。
而 `sameNorm` 第 4 步 `if (ka && kb) return ka === kb;` 会据此直接短路，连 `numConflict` 都走不到。

**实测**：
```
美国三季度GDP初值环比增长2%  vs  美国三季度GDP终值环比增长2.5%  →  true（被判同一件事）
```
两份数字不同的公报被合并，与注释承诺相反。

### 7.3 【严重】`sameFirmAction` 不校验「是不是同一个动作」

`4235–4242`：
```js
if (!ACT.test(a) || !ACT.test(b)) return false;   // ACT = 回购|增持|减持|并购|收购|中标|签约|发债|定增|分红
const na = firmNameOf(a), nb = firmNameOf(b);
if (!na || na !== nb) return false;
return ACT.test(a) && ACT.test(b);                 // ← 恒为 true，且重复判断
```
只要求「同公司 + 两边各命中**任意一个**动作词」，不比对动作是否相同。
`sameNews` 第 6 步直接 `if (sameFirmAction(t1,t2)) return true;`。

**实测**：
```
丰田将股票回购计划扩大至82亿美元  vs  丰田宣布减持股份1.2%  →  true（误合并）
丰田将股票回购计划扩大至82亿美元  vs  本田将股票回购计划扩大至82亿美元 → false（守门有效）
```
注释写「同一份公告的三种写法」，但判据比注释宽得多；单位换算场景（82 亿美元 ≈ 1.3 万亿日元）
确实需要放宽数字，动作词本身却不该放宽。

### 7.4 阈值 / 时间窗无单一真源（分级侧已治理，去重侧未治理）

§五 共 **10 类阈值 + 4 种时间窗** 散在 20+ 处。其中 `0.72` 一处引用 `DEDUP_THR`、
另一处（4658）硬编码同值；`6 小时` 同时以 `SYNC_WIN` 常量和 3 处字面量存在。
改一处忘一处必然口径漂移 —— 与分级 P1-A 治理前的 `2%/7% vs 3%/8%` 是同一类问题。

### 7.5 订阅源名单写了两份

`SUBSCRIBED_SRC`（2077，分级侧标红兜底用）与 `NO_MERGE_SRC`（4756，去重豁免用）
是**完全相同的正则** `/川普言论|口罩哥KZG/`，两个名字、两处定义。新增一个订阅源要改两处，漏一处就出现
「推文被新闻卡吸走 / 标红兜底不生效」的不一致。

### 7.6 `mergeGeoDup` 是明确记录过的妥协，但口径未再复核

`4894–4910` 只跑 `sameGeoEvent` + `sameCorpPersonnel` 两条窄判据。
注释写明原因：启动时不能跑全局 `dedupe`，否则「中际旭创回购 ≠ 联讯仪器回购」会被误合，
条数从 **73 骤降到 40**。这是诚实的取舍，但意味着**存量池里其它类型的重复永远清不掉**，
只能靠新规则对新抓取生效。

### 7.7 词表与判据膨胀、顺序耦合

- `DEDUP_SYN` 18 组**顺序敏感**（注释自承：「通过立法」要先于「立法」替换）；
  新增一条近义词要判断插在哪，插错会改变已有归一结果 —— 与分级侧「补丁只能往链头插」同构。
- `sameNews` 9 个短路分支 + 6 个专项判据，任一新判据都要决定「插在第几步」，
  因为 `return true` 会截断后面所有规则。
- 34 个常量里国家/机构/主体名单彼此重叠（`REL_GEO` 27 国、`DEDUP_GEO` 48 国、
  `PERSON_COUNTRY` 36 国、`GEO_ENTS` 13 类、`SYNC_ORG` 13 类），无组合派生，各管一摊。

### 7.8 归纳：为什么「重复怎么改还有」

```
一条重复漏过来
  → 看它在哪条链路漏的（同轮 / 跨轮 / 存量）← 三条判据不一致，先要分清
  → 补一条判据到「那条链路」
  → 另外两条链路没有同步补       ← 7.1，v58/v59 已发生过两次
  → 新判据插在哪个短路位置？     ← 7.7，顺序即语义
  → 阈值又多一个手写数字         ← 7.4
  → 下次换个写法 / 换个到达轮次，再报一次
```
**根因不是「缺规则」，是缺三样东西**：三条链路的**统一内核**、阈值的**单一真源**、
以及能表达「哪条链路命中了哪条判据」的**可观测决策轨迹**（分级侧 P2-A 已有 `_explain`，去重侧没有）。
